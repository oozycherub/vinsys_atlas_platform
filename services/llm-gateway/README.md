# llm-gateway (brick 5)

Every AI call in Atlas goes through this service. It handles model routing and failover, PII redaction before anything leaves the platform, structured-output validation, per-tenant budgets, the versioned prompt registry, a response cache, the evaluation log, and embeddings.

This is the first Python brick: Python 3.12, FastAPI, Pydantic v2, uv, ruff, mypy --strict and pytest.

Spec: [`docs/prompts/05-llm-gateway.md`](../../docs/prompts/05-llm-gateway.md) · Contract: [`openapi.yaml`](openapi.yaml) (generated by FastAPI; `make openapi-py` regenerates it, and a test fails if it drifts).

## Design

```
http/app.py          FastAPI routes, auth, RFC 9457 problem+json, request ids, SSE
  └─▶ application/   Gateway (messages, stream, embed), PromptRegistry, BudgetAdmin; ports.py
        └─▶ domain/  templates (render, delimiters), redaction (tokens, re-identification),
                     policy (injection score, budgets, cache key, failover, schema checks)
infrastructure/      psycopg pool + repositories, Anthropic and stub providers, Presidio,
                     memory / Redis store, Triton and stub embeddings, JWT, Kafka purge consumer
```

### A call, step by step (`POST /v1/llm/messages`)

1. **Prompt lookup.** The caller names `prompt_id@version`. The version must be active, and its registered `purpose` must match the request's purpose.
2. **Budget pre-check.** If the tenant has used up its monthly tokens, the call returns `429 BUDGET_EXCEEDED` with `Retry-After` (seconds until the month resets). Nothing is sent.
3. **Redaction (fail closed).** Redaction runs when the prompt is tagged `contains_candidate_text`, or when the caller passes `known_pii`. Three detectors are merged:
   - exact matches of the PII the caller already knows (name, email, phone);
   - deterministic email and phone patterns;
   - Presidio with spaCy NER.

   Each span becomes a token such as `[[PII_PERSON_3F2A9C1B]]`. If any detector fails, the call returns `503 REDACTION_FAILED` and nothing leaves the gateway.

4. **Rendering.** Untrusted variables (document text) are wrapped in `<document name="…">` tags, and any closing tag inside them is neutralised. The system prompt then tells the model to treat that text as data. Each untrusted variable gets a prompt-injection score from 0 to 1, which is returned and logged. The score is never acted on here: the delimiters and output schemas are the defence, and the scores feed review queues.
5. **Cache.** Only prompts registered as `deterministic` are cached, with a 24 h TTL. The key covers tenant, prompt version, route, redacted input and schema. Tokens are an HMAC keyed per tenant and month, so the same person gets the same token within a tenant and the cache works on redacted input. Two tenants never share a key or a token.
6. **Routing and failover.** Each route (`primary` → `claude-sonnet-5-5`, `fast` → `claude-haiku-5-5`, `eval` → `claude-opus-5-5`) has an ordered list of targets.
   - Only infrastructure failures (connection, timeout, 429, 5xx, overloaded) move on to the next target.
   - A rejected request (4xx) is final.
   - Each attempt's latency is recorded.
7. **Refusals.** On Sonnet 5.5 and Opus 5.5, Anthropic's server-side refusal fallback is on (`server-side-fallback-2026-07-01`, `fallbacks="default"`). A refusal that survives it returns `422 MODEL_REFUSED` with the category.
8. **Structured output.** The JSON Schema goes to the model as `output_config.format` and is checked again here. On a mismatch the model gets one repair turn with the validator's errors. If the output still does not match, the call returns `502 OUTPUT_SCHEMA_VIOLATION`.
9. **Re-identification.** Tokens are replaced with the real values only at the JSON Pointers the prompt allows (`reidentify_fields`; `*` matches any key or index; `""` means the whole text reply). Every other field keeps its tokens, so a model cannot be tricked into echoing PII somewhere nobody asked for it.
10. **Accounting.** Each call writes the following in one transaction:
    - the budget increment, plus `ai.budget.threshold_crossed.v1` the first time usage crosses the soft (80 %) or hard line in a month;
    - an `llm_calls` row: redacted input and output, attempts, tokens, latency and gateway overhead;
    - `ai.call.completed.v1` (metrics only).

### Tool use

Pass `tools`. When the model calls a tool, the response carries `tool_calls`, whose inputs are still pseudonymised, and a `session_id`. Continue the loop with `session_id` and `tool_results`.

- The tool results are redacted with the same token map before they go back to the model.
- The session holds the transcript and the token map for 1 h, and only the same tenant and prompt can use it.
- Thinking blocks are kept in the transcript, so the loop continues faithfully.

### Streaming (`POST /v1/llm/messages:stream`)

Server-sent events for text prompts: `meta`, then `delta`*, then `done`, or `error`.

- **Before the first event,** failures are ordinary problem+json responses, and failover still applies.
- **After output has started,** an interruption ends the stream with an `error` event and is logged as `STREAM_INTERRUPTED`. A second model never continues another model's half-finished answer.
- **Tokens are never split.** Re-identification holds back text that could be the start of a token until the token is complete.

### Embeddings (`POST /v1/embeddings`)

- **Model.** bge-m3 on Triton (KServe v2). In development the same model runs on a CPU instance group (`ATLAS_LLM_TRITON_URL`). With no Triton configured, a deterministic stub answers, and it names itself `stub-hash-1024`.
- **Model check.** The response always names the model that produced the vectors. taxonomy-svc's `GatewayEmbeddingClient` now rejects vectors from any model other than the one it asked for, so stub vectors can never be stored as bge-m3.
- **Batch and output.** At most 64 inputs per call. Vectors are L2-normalised.
- **Billing.** GPU seconds are charged to `tenant_id` when it is given; platform calls without one are not charged.
- **Redaction.** Purposes such as `resume_chunk` are anonymised (`[PERSON]`) before embedding.

### Who may call what

| Endpoint                                                  | Caller                                                                                       |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `POST /v1/llm/messages`, `:stream`                        | `service` with `llm:invoke`. A token bound to a tenant (`tid`) may only act for that tenant. |
| `POST /v1/embeddings`                                     | `service` with `embeddings:create`                                                           |
| `POST /v1/prompts`, `…/versions/{v}:retire`               | `super_admin`, or `service` with `prompts:write`                                             |
| `GET /v1/prompts/{id@v}`, `GET /v1/prompts/{id}/versions` | the above, or any `service`                                                                  |
| `GET /v1/tenants/{id}/ai-budget`                          | `super_admin`, or `tenant_admin` of that tenant                                              |
| `PUT /v1/tenants/{id}/ai-budget`                          | `super_admin` only (`PLATFORM_MANAGED_SETTING`, like tenant `limits`)                        |

Prompt versions are immutable. Re-registering identical content is a no-op, so retries are safe. Different content under an existing version is `409 PROMPT_VERSION_EXISTS`.

## Owned data (`0008_llm_gateway.sql`)

| Table                       | Holds                                                                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt_templates`          | Platform-level and immutable; the app role may only update `status`.                                                                                                |
| `tenant_ai_budget_settings` | Per-tenant monthly limits. Without a row, the configured defaults apply.                                                                                            |
| `tenant_ai_budgets`         | Usage per tenant and month (`YYYY-MM`, UTC), plus the alerted-at marks.                                                                                             |
| `llm_calls`                 | The evaluation log, partitioned monthly (2026-01 to 2028-12, plus a default partition). It never holds raw PII. The app role may insert and delete, but not update. |

All three tenant tables use strict RLS (`tenant_id = current_tenant_id()`).

## Events

| Direction | Event                            | Notes                                                                                                                              |
| --------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Produced  | `ai.budget.threshold_crossed.v1` | Level `soft` or `hard`, resource `tokens` or `gpu_seconds`; once per level per month.                                              |
| Produced  | `ai.call.completed.v1`           | Metrics only, never content.                                                                                                       |
| Consumed  | `tenant.tenant.purged.v1`        | Deletes the tenant's calls, usage and limits. De-duplicated through `processed_events`; malformed records go to `llm-gateway.dlq`. |

## Running and testing

```bash
uv sync                       # Python 3.12 from .python-version
uv run pytest --cov=llm_gateway
uv run python -m llm_gateway.main
```

The tests run against a real embedded Postgres (pgserver) with migrations 0001 and 0008 and RLS enforced, and against real Presidio. The Anthropic adapter is tested against a mocked HTTP transport, so the wire request (`output_config`, adaptive thinking, the fallback beta, no sampling parameters) and the error mapping are checked without a key.

## Decisions and known gaps

- **Budgets live in Postgres, not Redis.** The spec names a Redis key; this uses an atomic upsert counter instead. That gives exact accounting, threshold events in the same transaction as the usage they describe, and RLS. The pre-check is a read, so concurrent calls can overshoot a hard limit by at most the calls already in flight.
- **No `temperature` 0.** The 5.5 models reject sampling parameters, so cache eligibility is a template flag (`deterministic`). Thinking cannot be turned off on these models; it is adaptive.
- **One repair attempt.** §6 of the spec allows one repair; §4 says "2 repair attempts". This follows §6.
- **`tenant.tenant.settings_updated.v1` is not consumed.** Tenant settings have no AI-budget section, so budgets are set here, by staff, through `PUT …/ai-budget`.
- **Monthly partitions run to 2028-12.** A partition-maintenance job (run as the owner) must add later months; until then they land in the default partition.
- **Not done yet:** a Bedrock or Vertex provider adapter for cross-provider failover (the route config already supports it), and Redis-backed rate limiting per calling service.
