# Component Prompt 05: llm-gateway (Model Routing, Redaction, Quotas, Embeddings)

## 1. Context

- PRD §1.4 (LLMs and embeddings rows) and §4.1(i) (anonymisation pipeline).
- Brick 5. **First Python brick:** Python 3.12, FastAPI, Pydantic v2, uv, ruff, mypy --strict, pytest. Same hexagonal layout.
- Every AI call in the platform goes through here.

## Status

**Built.** Everything in §2–§8; acceptance tests 1–5 pass against real Postgres and Presidio. One repair attempt (per §6), budgets in Postgres rather than Redis, and `settings_updated` not consumed; see `services/llm-gateway/README.md` for these decisions and the remaining gaps. taxonomy-svc's `GatewayEmbeddingClient` now checks the response model.

## 2. Scope

**In**

- `POST /v1/llm/messages`: structured-output calls with a JSON Schema; tool use.
- `POST /v1/llm/messages:stream` (SSE).
- `POST /v1/embeddings`: self-hosted bge-m3 through Triton, with a CPU fallback for development.
- **Presidio redaction** before egress, with a reversible token map held in memory or Redis for 1 h.
- **Prompt registry:** versioned templates by `prompt_id@version`.
- Per-tenant token and GPU-second budgets (soft alert, hard degrade).
- Model routing and failover: primary `claude-sonnet-5-5`; fast path `claude-haiku-5-5`; offline evaluation `claude-opus-5-5`.
- Response cache keyed by (prompt_id, version, input hash), only for temperature-0 calls.
- Full evaluation logging: redacted input, output, latency, tokens.

**Out:** business prompts themselves (owned by calling bricks and registered here).

## 3. Owned data

- Migration `0008_llm_gateway.sql`: `prompt_templates`, `llm_calls` (partitioned monthly; no raw PII), `tenant_ai_budgets`.
- Redis: `t:{tid}:llm:budget:{yyyymm}`.

## 4. API contract

Service-to-service only: `service` role with scopes `llm:invoke` and `embeddings:create`. The request carries `tenant_id` (from the caller's verified context), `purpose` (for example `resume_extraction`), `prompt_id@version`, variables and `output_schema`.

Errors: `BUDGET_EXCEEDED` (429), `OUTPUT_SCHEMA_VIOLATION` (502 after 2 repair attempts), `PROVIDER_UNAVAILABLE` (503 after failover).

**Embeddings contract (already called by taxonomy-svc `GatewayEmbeddingClient`):**

`POST /v1/embeddings`, role `service` with scope `embeddings:create`. Request `{"model": "bge-m3", "input": ["..."], "purpose": "taxonomy_normalisation"}` (≤ 64 inputs). Response `{"model": "bge-m3", "data": [{"index": 0, "embedding": [1024 floats]}]}`, one item per input, matched by `index`. Vectors are L2-normalised.

## 5. Events

- **Produced:** `ai.budget.threshold_crossed.v1`, `ai.call.completed.v1` (metrics only).
- **Consumed:** `tenant.tenant.settings_updated.v1` (budgets), `tenant.tenant.purged.v1`.

## 6. Domain rules

- **Redaction is mandatory** for purposes tagged `contains_candidate_text`. A redaction failure fails the call (fail closed).
- **Structured outputs** are validated against the schema. On failure there is one repair retry with the validator error, then 502.
- **Document text** is wrapped in delimiters and labelled as data in system prompts. Prompt-injection classifier scores are attached to the response.

## 7. Non-functional

- Gateway overhead p95 < 40 ms.
- Embeddings: batch ≤ 64; p95 < 150 ms per batch on GPU.

## 8. Acceptance tests

1. PII in the input never reaches the provider stub; the output is re-identified for allowed fields only.
2. A schema violation triggers a repair, then a 502.
3. Budget exhaustion returns 429 and emits an event.
4. Primary provider down: the call fails over and the latency is recorded.
5. Cross-tenant cache isolation: the cache key includes `tenant_id`.

## 9. Deliverables

`services/llm-gateway/` (Python), `pyproject.toml`, `openapi.yaml` (generated by FastAPI and checked in), a provider adapter interface with Anthropic and stub implementations, and the Triton embedding adapter.
